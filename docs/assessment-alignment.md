# Assessment Alignment

This document maps the university marking criteria in `docs/guide.txt` to evidence in this repository and its maintained project documentation.

## Deliverables

- **Dissertation**: 85%
- **Video presentation**: 5%
- **Professional conduct**: 10%

## Analysis (15%)

Show a clear problem statement, realistic scope, requirements, and awareness of related products.

Evidence:
- `docs/overview.md`
- `docs/platform-vision.md`
- `docs/requirements.md`
- `docs/related-products.md`

## Software product (40%)

Show a working system with a clear architecture, documented boundaries, and maintainable implementation choices.

Evidence:
- `docs/architecture/system-architecture.md`
- `docs/architecture/backend-architecture.md`
- `docs/architecture/frontend-architecture.md`
- `docs/architecture/API_DOCUMENTATION.md`
- `docs/PROACTIVE_SYSTEM_DEEP_DIVE.md`
- `docs/features.md`
- `docs/configuration.md`
- `docs/security.md`
- `README.md`

## Evaluation (10%)

Show test coverage, operational validation, limitations, and a credible evaluation narrative.

Evidence:
- `docs/testing-evaluation.md`
- `docs/operations.md`
- `docs/proactive-IR.md`
- `docs/dataset/trec-covid/README.md`

## Dissertation quality (20%)

Show coherent structure, justified decisions, accurate claims, and correct treatment of licensing and tool use.

Evidence:
- `docs/licensing.md`
- `docs/ai-assisted-engineering.md`
- `docs/project-management.md`

## Professional conduct (10%)

Show incremental progress, sensible tool use, and clear project management.

Evidence:
- Git commit history
- `docs/project-management.md`
- Meeting records and time tracking maintained outside the repository and submitted separately where required

## Presentation (5%)

Show the system clearly, walk through real workflows, and tie the demo back to architecture and evaluation evidence.
